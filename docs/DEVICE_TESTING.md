# Device testing checklist

CLAUDE.md: Expo Go or a simulator is **not** release acceptance. Notifications, secure storage and accessibility must be tested on a
development build on a real iPhone and a real Android phone, and anything not tested must be reported as untested. This file lists
what has to be checked. Record each result (pass, fail, or not tested) in `docs/STATUS.md`.

## Getting a development build

`expo-dev-client` is installed. A development build is a version of the app with Expo's tools built in, so native features work.

- **iPhone (local):** needs Xcode and CocoaPods (both installed on this machine), then
  `npx expo run:ios --device` for a connected iPhone (free Apple ID signing works for your own phone), or `npx expo run:ios` for the simulator.
  A simulator build was made and launched on 2026-10-28 (iPhone 16 Plus). It shows the dev launcher; tap **Open** on iOS's "Open in Quest Blocks?" prompt.
- **Android (local):** needs Android Studio and its SDK (**not installed**), then `npx expo run:android --device`.
- **Cloud (EAS):** `eas.json` has two profiles: `development` (internal distribution; Android makes an APK) and `development-simulator` (iOS simulator build).
  Run `npx eas-cli@latest login` and `npx eas-cli@latest init` yourself (needs your Expo account), then
  `npx eas-cli@latest build --profile development --platform android`. Installing on a real iPhone through EAS needs an Apple Developer account.
  No EAS build has been run yet.
- **Your own content:** a local build (`npx expo run:ios --device`) bundles `content/private/household.json` if it exists (see `docs/PRIVATE_CONTENT.md`); an EAS cloud build does not, by design.
- `ios/` and `android/` are generated by `npx expo prebuild` and are gitignored. Change native settings in `app.json`, not in those folders.
- Identifiers: `com.ejkinney0312.mend` on both iOS and Android (chosen by Erin; permanent after the first store upload, so provisional until each store accepts it).
- Permissions audited on the generated projects: no microphone, Face ID or background modes. `app.json` turns these off for `expo-audio` and
  `expo-secure-store` and blocks the Android storage permissions. Development builds still include INTERNET, SYSTEM_ALERT_WINDOW and a local-network
  usage string for the dev server. Release builds drop them: `eas.json` has a `production` profile that sets `QUEST_BLOCKS_RELEASE=1`, which `app.config.ts` reads
  (locally: `QUEST_BLOCKS_RELEASE=1 npx expo prebuild`). Confirm on a real release build that the app still works without INTERNET (it should; P0 has no network features).
- After building, start the server with `npx expo start --dev-client` and open the app on the phone. Plain `npx expo start --go` still opens Expo Go.

## Reminders (M14)

Use fictional demo data. For each, note the phone, OS version, and result.

1. **Permission.** Fresh install: the caregiver panel says "Not asked yet". Turn a quest's reminder on: the system prompt appears **once**.
   Choose Allow: the panel says "On" and shows a next-reminder time. Repeat with Don't Allow: the panel says "Off", shows the explanation, and
   "Open phone settings" opens the right place; turning notifications on there and returning to the app schedules reminders.
2. **App closed.** Set a reminder 3 minutes ahead. Close the app completely (swipe away). The reminder arrives at about the right time.
   The text is only "Quest Blocks / A quest is ready when you are." (or the caregiver's wording). Note how late it was on Android.
3. **Lock screen.** With the phone locked, the reminder shows no quest name or detail. Check with previews on and off.
4. **After a restart.** Set a reminder 5 minutes ahead, restart the phone, do not open the app. The reminder still arrives.
5. **Quiet hours.** Set a reminder inside quiet hours at 6:30 AM (it should arrive at 7:00 AM that day) and a daily quest's reminder at 10:00 PM (it should arrive at
   7:00 AM the next morning, not at night). A quest that is not due the next morning (a weekly or every-3-days quest) gets no 10:00 PM reminder at all.
   Change quiet hours and confirm the next-reminder time changes. Nothing should ever arrive during quiet hours.
6. **Finished quest.** Finish a quest before its reminder time (including one finished by a caregiver's approval). No reminder arrives for it that day; the next due day still does.
7. **Time zone.** Change the phone's time zone (or travel), open the app, and check that the next reminder time matches the new local time.
   Check the day the clocks change if you can.
8. **No duplicates.** Change a reminder's time several times, open and close the app several times: only one reminder arrives per due day.
9. **Foreground.** With the app open on Today when a reminder is due: a quiet banner, no sound.
10. **Focus / Do Not Disturb.** Confirm what happens, and that nothing is sent during quiet hours.
11. **Android only.** Android 13+: the permission prompt appears (the "Quest reminders" channel exists first). Android 14: confirm reminders still arrive without
    the exact-alarm permission, and note the delay.
12. **Two weeks.** Leave the app unopened for 14 days and note when reminders stop (expected: after the planned window).

## Routine reminders and the Health tab (F19)

Not yet tried on any device. The daily repeating notifications are the part the Expo docs do not describe for reboots or time-zone changes, so check each:

1. **Add one.** Caregiver > Routine reminders > "Drink water" (or any): set it to "Every hour" from a time a few minutes ahead. It shows on the Health tab with "Next today".
2. **App closed.** Close the app completely. The reminder arrives at the right time, and again the next hour.
3. **Lock screen.** With "Show the words" off, a locked phone shows only "Mend / A reminder is ready." With it on, the name shows.
4. **After a restart.** Set one 5 minutes ahead, restart the phone, do not open the app. It still arrives.
5. **Next day.** The same times arrive the day after without opening the app.
6. **Time zone and daylight saving.** Change the phone's time zone (or set the clock across a daylight-saving change), open the app once, and check the times still match the clock on the wall.
7. **Switch off and delete.** Switching off stops it at once; deleting removes it; neither affects the quest reminders.
8. **Too many.** Add enough times to pass 20 a day: the Health tab and Caregiver mode say one did not fit.
9. **Days of the week.** Add a reminder on only some days, including today, a few minutes ahead: it arrives. Move it to a day that is not today: it does not. This is the **weekly** trigger, which the Expo docs describe mainly for Android, so check it on the iPhone with the app closed and after a restart.
10. **Private name.** Switch "Keep the name private" on: the Health tab says "Private reminder" and shows only times; caregiver mode still shows the name.
11. **VoiceOver, 200% text and Android** on the Health tab, the day picker and the form.
12. **Today card.** With a reminder switched on, Today shows "Next reminder" with the right time; tapping it opens Health. With every reminder off, the card is gone. A private name shows as "Private reminder".
13. **Tap a reminder.** Tap a routine reminder from the lock screen with the app (a) in the background and (b) completely closed: both open the Health tab. Tap a quest reminder: it opens Today. Check VoiceOver reads the Today card as a button.
