# Quest Blocks

A native iOS and Android app (React Native, Expo, TypeScript) that helps an adult early reader finish
chores independently. Each chore is a **Quest** made of **Missions**. Rook, an original encouraging
companion, gives tips, and finishing quests grows a block village. A caregiver controls content and
rewards behind a PIN.

**Status: early development.** The foundation, local database and schedule engine exist, and Today
shows the day's quests. Playing a quest, rewards, the caregiver PIN, Rook, the village and reminders
are not built yet. Everything on screen is fictional **demo** content. Not ready for the App Store or
Google Play.

## Run it

Requires Node 22.5 or later (the database tests use Node's built-in SQLite) and npm.

```bash
npm install
npx expo start --ios      # iOS simulator (installs Expo Go if needed)
npx expo start            # then press i (iOS) or a (Android), or scan the QR code with Expo Go
```

Plain `npx expo start --go` opens Expo Go. `expo-dev-client` is installed, so `npx expo start` prefers a development build when one exists. Expo Go is
enough for most screens, but **reminders, secure storage and the other native features must be tested on a development build on a real phone**; see
`docs/DEVICE_TESTING.md` for how to make one and what to check.

The app stores data on the device only. There is no backend, no account and no analytics. SQLite on web
is not set up, so the web build shows a notice instead of the app. Expo Go is enough for now; features
such as notifications and secure storage will need a development build.

In development builds the app seeds a few fictional demo quests on first launch. Release builds start
empty. To start over, delete the app from the simulator and run it again.

## Checks

```bash
npx tsc --noEmit          # type check (strict)
npm run lint              # ESLint (eslint-config-expo)
npm test -- --runInBand   # Jest (jest-expo)
npx expo-doctor           # Expo project health
```

`expo-env.d.ts` is generated by `expo start` and gitignored. After a fresh clone, run `npx expo start`
once, or type checking will fail on the `.css` imports.

Tests cover the domain rules and the database (migrations, rewards ledger, schedules) against real SQLite
through Node. They do not replace testing on real iPhone and Android hardware.

## Layout

```
src/app/         Expo Router screens (Today, Progress, Village, Caregiver, quest)
src/components/  Shared UI (themed text/view, tabs, screen)
src/constants/   Theme: palette, sizing, spacing
assets/sounds/   The quest chime (original; regenerate with `node scripts/generate-chime.js`)
src/domain/      Pure rules and types: schedules, dates, rewards, demo content (no React, no native code)
src/db/          SQLite: versioned migrations, queries, seeding, schedule instances, payouts
src/services/    Device services: speech, secure storage, PIN key derivation and the caregiver PIN service
src/features/    Screen logic that connects the database to the UI
```

## Privacy

Use only fictional data in this repository. Do not commit real household details, PINs, care instructions,
`.env` files or signing credentials. Reward spending is deliberately switched off until the household
confirms how emeralds are spent (see `docs/DECISIONS.md`).

The only third-party code is the open-source libraries listed in `package.json`.
